Trolley-Augmented
AMR Tracker

When an AMR tows a trolley, the whole system's dynamics change — but you can't always put sensors on the trolley. Can you learn the residual without modeling it?

the problem

Autonomous Mobile Robots in warehouses often tow passive trolleys: unpowered, unsteered carts that couple to the AMR mechanically. The trolley adds significant inertia, changes the system's effective turning radius, and creates oscillation during acceleration.

Standard AMR state estimators (wheel odometry + IMU, or LiDAR-based localization) are calibrated for the base robot alone. Adding the trolley degrades tracking accuracy — the estimator's dynamics model is wrong. The straightforward fix is to model the trolley explicitly. But that requires knowing trolley mass, hitch geometry, and wheel friction — parameters that vary with load and are rarely measured.

the approach

Instead of modeling the trolley, the goal is to model the residual — the discrepancy between what the base estimator predicts and what the system actually does. If that residual can be learned from data, it can be subtracted at runtime to recover accurate tracking without any explicit trolley model.

Two candidate architectures: a Gaussian Process Regression (GPR) model that gives uncertainty estimates alongside the residual prediction, which is useful for knowing when to trust the correction; and a small MLP trained online as the trolley's load changes. The GPR is interpretable and sample-efficient; the MLP can adapt faster to distribution shift.

The inputs to the residual model are: current AMR velocity, angular velocity, and a short history of commanded velocities — features that correlate with trolley-induced dynamics without requiring any direct trolley observation.

current status

Simulation environment set up in Gazebo with a parameterized trolley model. Initial data collection and GPR baseline underway. Comparing tracking error with and without the learned residual correction across different trolley loads and maneuver profiles.
