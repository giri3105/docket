Sudoku Solver with
Real-Image Dataset

MNIST is a clean benchmark. Real Sudoku puzzles are not. The interesting problem is building a recognizer that works on what people actually photograph.

why not MNIST

Most "Sudoku solver" projects on GitHub use a digit classifier trained on MNIST — a dataset of handwritten digits photographed under controlled conditions. Real Sudoku grids use printed fonts, come from phone cameras at varying angles, have bleed-through from the page behind, and often have partial occlusions from fingers or shadows.

A model trained on MNIST fails badly on real Sudoku images. The gap isn't a generalization failure in the traditional sense — it's a domain mismatch. The solution is obvious once you see it: train on the actual domain.

dataset & training

Built a dataset of digit crops extracted from real photographed Sudoku puzzles — diverse fonts, print qualities, and capture conditions. Combined with augmentation (perspective warp, noise, brightness jitter) to cover edge cases the raw collection missed.

The classifier is a compact CNN trained in PyTorch. The architecture is deliberately small — the digit recognition problem doesn't need depth once the domain shift is handled; it needs the right data.

pipeline

The full pipeline: photograph → grid detection (OpenCV contour + perspective transform) → cell segmentation → digit classification → constraint propagation solver → overlay solution back onto the original image.

The solver itself uses backtracking with constraint propagation — fast enough for any valid puzzle, and deterministic. The interesting engineering is entirely in the vision front-end.
